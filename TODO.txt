    3. HarmonizedHuman vs. a real majority vote from the raw MultiHuman
       batches -> harmonized_consensus_check.csv, harmonized_vs_true_majority_vote.csv.
       CORRECTED after two passes (first pass used a naive strict-majority
       presence rule and got this wrong, see history):
         - Presence: HarmonizedHuman's real rule is "present if ANY covering
           annotator mentioned it" (confirmed: all genuine 1-1 ties resolve

           agreement = 92.7%, kappa = 0.853 (n=1050, >=2 covering annotators,

           matches that value 88.9% of the time, as expected. When they were
           SPLIT (n=89, i.e. real disagreement), HarmonizedHuman matches the
           plurality/most-common value only 23.6% of the time.
       CONCLUSION: a real majority vote would NOT be better. HarmonizedHuman
       tracks a simple vote closely on easy, unanimous cases, but on exactly
       the hard cases where annotators genuinely disagreed, the human
       harmonizer picked something other than the majority answer ~3 times
       out of 4 -- consistent with real semantic reconciliation (recognizing
       differently-worded spans as the same concept, correcting an
       annotator's error) rather than frequency counting. A mechanical
       majority vote would systematically get the hard cases wrong in a way
       the actual curated file does not. Also independently confirmed: 7
